The skill should deeply research products, user flows, UI patterns, and screens using the Mobbin MCP server, then create a raw Markdown file called [name]-mobbin-benchmark.md.

This should be an intentionally messy, extremely detailed first-pass benchmark. Do not worry about making it polished, concise, client-ready, or perfectly organized. Capture as much useful information as possible so we can refine, deduplicate and restructure it later.

Research anything relevant, including:

• Similar products
• Similar user flows
• Similar features
• UX patterns
• UI patterns
• Navigation
• Information architecture
• Layout
• Visual hierarchy
• Interaction design
• Copywriting
• Empty states
• Error states
• Forms
• Onboarding
• Search
• Filters
• Creation flows
• Editing flows
• Settings
• Dashboards
• Pricing
• Paywalls
• Notifications
• Lists
• Tables
• Cards
• Mobile patterns
• Desktop patterns
• AI interactions
• Progressive disclosure
• Advanced functionality
• Edge cases
• Interesting implementation details
• Unusual ideas
• Clever microinteractions
• Anything potentially useful

For every finding, include as much as possible:

• Product
• Screen or flow
• Screenshot description
• Where it appears
• What it does
• Why it is interesting
• UX rationale
• Advantages
• Disadvantages
• Possible use cases
• Adaptation ideas
• Similar patterns found elsewhere
• Questions worth investigating
• Anything else worth capturing

Prefer breadth over conclusions.

Collect many examples instead of selecting only the "best" ones.

Include duplicate or overlapping findings when useful. Different implementations of the same idea are valuable.

If several products solve the same problem differently, include every approach.

Do not remove ideas because they seem unrealistic, niche or low quality. They may become valuable later.

Clearly separate observations from assumptions.

Use headings, bullets, tables, screenshots references, notes, rough ideas and unfinished thoughts freely.

Do not summarize early.

Do not optimize for readability.

Optimize for collecting the maximum amount of potentially useful product knowledge into a single Markdown document.
