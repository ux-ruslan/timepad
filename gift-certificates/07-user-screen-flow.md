Источник: PRD в `gift-certificates/` (`00`–`06`).  
`04-decisions.md` пуст: зафиксированных продуктовых решений нет. При конфликте приоритет из `00-project.md`: decisions → requirements (`02-roadmap.md`) → user flows (`03`) → open questions → roadmap.

## Условные обозначения

| Форма | Смысл | Mermaid |
| --- | --- | --- |
| Прямоугольник | Экран | `[Экран]` |

## 1. Покупка сертификата

Покрывает сценарий 1 из `03-user-flows.md` и MVP из `06-roadmap.md`: фиксированные номиналы, один или несколько сертификатов в заказе, электронная доставка покупателю, уникальный код на каждый сертификат.

```mermaid
flowchart TD
  start([Вход: пользователь открывает страницу сертификатов]) --> landing[Страница подарочных сертификатов]

  %% Открытый вопрос: где живёт страница — Афиша, timepad.ru, отдельный URL?
  landing --> oq_where[Где точка входа в покупку?]:::oq

  landing --> chooseNom[Экран / блок выбора номинала]
  chooseNom --> nomOk{Номинал выбран?}
  nomOk -->|нет| chooseNom
  nomOk -->|да| qty[Экран / блок количества сертификатов]

  %% Открытый вопрос: нужен ли произвольный номинал? В MVP — только фиксированные.
  qty --> oq_custom[Нужен ли произвольный номинал?]:::oq

  qty --> qtyOk{Количество валидно?}
  qtyOk -->|нет / пусто / некорректно| qtyErr[Сообщение об ошибке количества]
  qtyErr --> qty
  qtyOk -->|да| recipientQ{Нужны данные получателя?}

  %% TODO: PRD говорит «при необходимости» — критерий необходимости не зафиксирован.
  recipientQ -->|TODO: когда обязательно| recipient[Форма данных получателя]
  recipientQ -->|не нужны / пропуск| checkoutPrep
  recipient --> recipientOk{Данные получателя валидны?}
  recipientOk -->|нет| recipientErr[Ошибка валидации получателя]
  recipientErr --> recipient
  recipientOk -->|да| checkoutPrep

  %% Открытый вопрос: массовая покупка и отправка нескольким получателям.
  recipient --> oq_mass[Как организовать отправку нескольким получателям?]:::oq

  checkoutPrep[Экран оформления заказа сертификатов] --> payStart([Инициация оплаты])
  payStart --> payUi[Экран оплаты банковской картой]
  payUi --> payResult{Оплата успешна?}

  payResult -->|ошибка оплаты / отказ / таймаут| payFail[Экран ошибки оплаты]
  payFail --> retry{Повторить оплату?}
  %% TODO: поведение повтора и отмены заказа не описано в PRD.
  retry -->|да TODO| payUi
  retry -->|нет TODO| landing

  payResult -->|успех| issue([Создать заказ: N сертификатов, каждому уникальный код])
  issue --> deliverBuyer([Электронная доставка покупателю: email и/или телефон])
  deliverBuyer --> success[Экран успешной покупки]
  success --> downloadOpt{Скачать сертификат?}
  downloadOpt -->|да| download([Выдать файл / страницу сертификата для скачивания])
  download --> success
  downloadOpt -->|нет / позже| postBuy[Экран / письмо с кодом, номиналом, инструкцией, ссылкой на Афишу]

  %% Открытый вопрос: отложенная отправка и персональное поздравление — после MVP.
  postBuy --> oq_delay[Нужна ли отложенная отправка?]:::oq
  postBuy --> oq_bind[Нужна ли привязка сертификата к аккаунту?]:::oq

  classDef oq fill:#FFA500,stroke:#CC7000,color:#000
```

## 3. Использование сертификата при оплате билета

Сценарий 3–4 из `03`, правила из `02-roadmap.md` (requirements), ограничения MVP из `06`.

```mermaid
flowchart TD
  event([Пользователь оформляет билет на событие]) --> eventType{Событие с оплатой через Timepad?}

  eventType -->|бесплатное| noCertFree[Оплата без сертификата / поле не применимо]
  %% TODO: скрывать поле ввода кода или показывать ошибку при вводе — не описано.
  noCertFree --> oq_free[Как UX для бесплатных событий?]:::oq

  eventType -->|платное| cart[Экран корзины / оплаты билета]
  cart --> wantCert{Ввести код сертификата?}
  wantCert -->|нет| cardOnly[Оплата банковской картой]
  wantCert -->|да| codeInput[Поле ввода кода сертификата]

  codeInput --> validate([Проверки: существует, активен, не заблокирован, баланс, подходит для заказа])

  validate --> exists{Существует?}
  exists -->|нет| errExists[Ошибка: сертификат не найден]
  errExists --> codeInput

  exists -->|да| active{Активен?}
  active -->|нет| errActive[Ошибка: сертификат неактивен]
  %% TODO: причины неактивности для текста ошибки — срок, возврат, иное — не зафиксированы.
  errActive --> codeInput

  active -->|да| blocked{Заблокирован?}
  blocked -->|да| errBlock[Ошибка: сертификат заблокирован]
  errBlock --> codeInput

  blocked -->|нет| balance{Доступный баланс > 0?}
  balance -->|нет| errZero[Ошибка: баланс исчерпан]
  errZero --> codeInput

  balance -->|да| suitable{Подходит для оплаты этого заказа?}
  %% Правила из requirements: не на бесплатные; не на покупку других сертификатов; события с оплатой через Timepad.
  suitable -->|нет: покупка сертификатов| errBuyCert[Ошибка: нельзя оплатить сертификатом другой сертификат]
  errBuyCert --> codeInput
  suitable -->|нет: иное TODO| errSuit[Ошибка: сертификат не подходит для заказа]
  errSuit --> codeInput

  suitable -->|да| already{В заказе уже применён сертификат?}
  %% MVP: один сертификат в одном заказе.
  already -->|да| errMulti[Ошибка: в заказе уже есть сертификат]
  errMulti --> codeInput
  %% Открытый вопрос / после MVP: несколько сертификатов в одном заказе.
  already --> oq_multi[Можно ли применять несколько сертификатов?]:::oq

  already -->|нет| promoQ{В заказе есть промокод / скидка?}
  promoQ -->|да| applyPromo([Сначала применить скидку или промокод])
  promoQ -->|нет| applyCert
  applyPromo --> applyCert([Применить сертификат к билетам и сервисному сбору])

  applyCert --> reserve
  %% Открытый вопрос: как резервировать баланс и предотвратить параллельное списание.
  reserve([TODO: резерв баланса на время оплаты?]) --> oq_reserve[Как резервировать баланс? Как предотвратить параллельное списание?]:::oq

  reserve --> compare{Баланс сертификата >= сумма к оплате после скидки?}

  compare -->|да, хватает| payFullCert([Списать сумму заказа с баланса сертификата])
  payFullCert --> ticketOk[Экран успешной покупки билета]
  payFullCert --> balLeft([Сохранить остаток, если был])

  compare -->|нет, не хватает| splitPay[Экран частичной оплаты: сертификат + доплата картой]
  splitPay --> cardPay([Оплата остатка банковской картой])
  cardPay --> cardRes{Доплата успешна?}
  cardRes -->|нет| splitFail[Ошибка доплаты]
  %% TODO: откат резерва / снятие применения сертификата при ошибке доплаты — не описано.
  splitFail --> splitRetry{Повторить доплату?}
  splitRetry -->|да TODO| cardPay
  splitRetry -->|нет TODO| cart
  cardRes -->|да| debit([Списать доступный баланс сертификата, остаток по карте])
  debit --> ticketOk
  debit --> balLeft

  balLeft --> done([Показать / обновить остаток сертификата])

  %% Открытый вопрос: частичная оплата на стороне эквайера.
  splitPay --> oq_acq[Как проводить частичную оплату: сертификат + карта?]:::oq

  classDef oq fill:#FFA500,stroke:#CC7000,color:#000
```

### Матрица проверок при вводе кода

Порядок и тексты ошибок в PRD не зафиксированы (`TODO`). Логические проверки из `03`:

1. Существует ли сертификат  
2. Активен ли он  
3. Не заблокирован ли  
4. Какой баланс доступен  
5. Подходит ли для оплаты заказа  

Дополнительно из requirements / MVP:

- не для бесплатных событий  
- не для покупки других сертификатов  
- промокод и сертификат можно вместе: сначала скидка/промокод, затем сертификат  
- один сертификат на заказ (MVP)  
- покрытие билетов и сервисного сбора  
- остаток сохраняется; пополнить сертификат нельзя

## 4. После покупки билета: остаток и повторное использование

```mermaid
flowchart TD
  used([Сертификат частично или полностью списан]) --> check{Остаток > 0?}
  check -->|да| keep([Сохранить остаток])
  keep --> reuse[Пользователь снова вводит тот же код на другом заказе]
  reuse --> useFlow([См. поток «Использование сертификата»])
  check -->|нет| empty[Сертификат с нулевым балансом]
  empty --> emptyTry{Попытка применить снова?}
  emptyTry -->|да| errZero[Ошибка: баланс исчерпан]
  emptyTry -->|нет| stop([Конец])

  %% Сертификат нельзя пополнить — requirements.
  empty --> noTopup[Нет экрана пополнения сертификата]
```

## 6. Возврат остатка сертификата через поддержку

MVP: ручной возврат остатка через поддержку. Самостоятельной формы в MVP нет (после MVP).

```mermaid
flowchart TD
  userNeed([Пользователь хочет вернуть остаток сертификата]) --> self{Есть самообслуживание?}
  self -->|нет, MVP| supportEntry[Канал поддержки / форма обращения]
  self -->|после MVP| selfForm[Самостоятельная форма возврата]

  supportEntry --> ask[Пользователь передаёт код и TODO: доказательства владения]
  ask --> oq_proof[Какой порядок подтверждения владения сертификатом?]:::oq
  ask --> oq_party[Кто юридически продаёт / кому возвращать деньги?]:::oq

  ask --> agent([Оператор: поиск сертификата в админке])
  agent --> status{Сертификат найден, не заблокирован, есть остаток?}
  status -->|нет| supportNo[Ответ поддержки: возврат невозможен / уточнение]
  status -->|да| manual([Ручной возврат остатка])
  manual --> done[Сообщение пользователю об итоге возврата]

  %% Открытый вопрос: чеки, эквайер, давние сертификаты — вне UI, влияют на исход.
  manual --> oq_acq2[Поддерживает ли эквайер возврат спустя месяцы/годы?]:::oq

  classDef oq fill:#FFA500,stroke:#CC7000,color:#000
```
